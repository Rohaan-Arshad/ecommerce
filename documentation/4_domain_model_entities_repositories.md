# 4 — Domain Model: Entities, Enums, Repositories, DTOs

The "domain model" is the set of Java objects that represent your data. This file
explains each one, and — as requested — what **every import** does.

---

## 4.1 `entity/AuthProvider.java` — an enum

```java
package com.ecommerce.entity;

public enum AuthProvider {
    LOCAL,
    GOOGLE,
    MICROSOFT
}
```

An **enum** is a fixed list of allowed values. `AuthProvider` records *how* a user
authenticates. It matches the `CHECK` constraint on the `users.auth_provider`
column in your SQL schema, so the Java code and the database agree on the allowed
values. No imports needed — enums are plain Java.

## 4.2 `entity/UserStatus.java` — an enum

```java
public enum UserStatus { ACTIVE, INACTIVE, BLOCKED }
```

The account state. `ACTIVE` users can log in; `INACTIVE`/`BLOCKED` cannot (checked
in `AuthService`). Matches `users.status`'s `CHECK` constraint.

## 4.3 `entity/Role.java` — the `roles` table

### Imports

| Import | What it does |
|--------|--------------|
| `jakarta.persistence.Entity` | Marks the class as a JPA entity (mapped to a table). |
| `jakarta.persistence.Table` | Lets us name the table explicitly (`roles`). |
| `jakarta.persistence.Id` | Marks the primary‑key field. |
| `jakarta.persistence.GeneratedValue` | Says the id is auto‑generated by the DB. |
| `jakarta.persistence.GenerationType` | The strategy enum; we use `IDENTITY` (MySQL auto‑increment). |
| `jakarta.persistence.Column` | Configures a column (name, length, unique, nullability). |

### Body

```java
@Entity
@Table(name = "roles")
public class Role {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "name", nullable = false, unique = true, length = 50)
    private String name;

    public Role() {}
    public Role(String name) { this.name = name; }
    // getId/setId/getName/setName ...
}
```

- `@Entity` + `@Table(name="roles")` → this object *is* a row in the `roles` table.
- The `id` is the auto‑increment primary key.
- `name` is unique (`CUSTOMER`, `ADMIN`).
- Two constructors: the no‑arg one is required by JPA; the `Role(String name)` one
  is a convenience for creating a role in code.

## 4.4 `entity/User.java` — the `users` table

### Imports

All the same JPA annotations as `Role`, plus:

| Import | What it does |
|--------|--------------|
| `jakarta.persistence.EnumType` & `Enumerated` | Store an enum as text (`STRING`) in the DB rather than a number. Used for `authProvider` and `status`. |
| `jakarta.persistence.FetchType` | Controls when related data loads; we use `EAGER` for roles so they're always available. |
| `jakarta.persistence.ManyToMany` | A user can have many roles and a role many users — the `user_roles` join table. |
| `jakarta.persistence.JoinTable` / `JoinColumn` | Describe that join table and its two foreign‑key columns. |
| `org.hibernate.annotations.CreationTimestamp` | Hibernate fills this field with the current time on INSERT. |
| `org.hibernate.annotations.UpdateTimestamp` | Hibernate updates this field with the current time on every UPDATE. |
| `java.time.LocalDateTime` | The Java type for the timestamps. |
| `java.util.HashSet` / `Set` | Holds the set of roles (a Set = no duplicates). |

### Fields (mapped to columns)

| Field | Column | Notes |
|-------|--------|-------|
| `id` | `id` | Primary key, auto‑increment |
| `firstName` | `first_name` | Required |
| `lastName` | `last_name` | Optional |
| `email` | `email` | Unique — the login identifier |
| `password` | `password` | **BCrypt hash** for LOCAL users; `null` for OAuth users |
| `phone` | `phone` | Optional |
| `authProvider` | `auth_provider` | Enum stored as text: LOCAL/GOOGLE/MICROSOFT |
| `providerUserId` | `provider_user_id` | Google/Microsoft `sub` id; `null` for LOCAL |
| `status` | `status` | Enum: ACTIVE/INACTIVE/BLOCKED |
| `emailVerified` | `email_verified` | `true` for OAuth users (provider verified it) |
| `createdAt` | `created_at` | Auto‑set on insert |
| `updatedAt` | `updated_at` | Auto‑set on update |
| `roles` | via `user_roles` | Many‑to‑many set of `Role` |

### Helper methods

```java
public String getFullName() {
    return lastName == null || lastName.isBlank()
            ? firstName
            : firstName + " " + lastName;
}
public void addRole(Role role) { this.roles.add(role); }
```

- `getFullName()` — builds a display name from first + last (used on the dashboard).
- `addRole(...)` — convenience to attach a role.

The rest of the class is plain getters/setters (written by hand because we removed
Lombok).

## 4.5 `repository/UserRepository.java`

### Imports

| Import | What it does |
|--------|--------------|
| `com.ecommerce.entity.AuthProvider` / `User` | The types this repository works with. |
| `org.springframework.data.jpa.repository.JpaRepository` | The base interface that gives us `save`, `findById`, `findAll`, `delete`, … for free. |
| `org.springframework.stereotype.Repository` | Marks this as a Spring‑managed data‑access bean. |
| `java.util.Optional` | A container that may or may not hold a value — avoids `null` surprises. |

### Body

```java
@Repository
public interface UserRepository extends JpaRepository<User, Long> {
    Optional<User> findByEmail(String email);
    boolean existsByEmail(String email);
    Optional<User> findByAuthProviderAndProviderUserId(AuthProvider p, String id);
}
```

This is an **interface** — we never write the implementation. Spring Data JPA reads
the *method names* and generates the SQL automatically:

- `findByEmail("a@b.com")` → `SELECT * FROM users WHERE email = ?`
- `existsByEmail(...)` → `SELECT COUNT(...) > 0 …`
- `findByAuthProviderAndProviderUserId(...)` → `… WHERE auth_provider = ? AND provider_user_id = ?`

`Optional<User>` means "maybe a user, maybe nothing" — you must handle the
"not found" case, which prevents `NullPointerException`s.

## 4.6 `repository/RoleRepository.java`

```java
@Repository
public interface RoleRepository extends JpaRepository<Role, Long> {
    Optional<Role> findByName(String name);
}
```

Same idea: `findByName("CUSTOMER")` looks up a role by its name. Used when we
assign the default `CUSTOMER` role to new users.

## 4.7 DTOs — Data Transfer Objects

A **DTO** is a small object that defines the *shape* of data crossing a boundary
(browser ⇆ server). We use Java **records**, which are immutable data holders that
auto‑generate a constructor, accessors, `equals`, and `toString`.

### `dto/RegisterRequest.java`

Imports (all from `jakarta.validation.constraints`):

| Import | What it does |
|--------|--------------|
| `@NotBlank` | Field must not be null/empty/whitespace. |
| `@Email` | Field must look like an email address. |
| `@Size` | Enforces min/max length. |

```java
public record RegisterRequest(
        @NotBlank @Size(max=100) String firstName,
        @Size(max=100) String lastName,
        @NotBlank @Email @Size(max=255) String email,
        @NotBlank @Size(min=6, max=72) String password,
        @Size(max=30) String phone) {}
```

When a controller marks this `@Valid`, Spring checks all these rules *before* your
code runs; if any fail, `ApiExceptionHandler` returns a clean error.

### `dto/LoginRequest.java`

```java
public record LoginRequest(
        @NotBlank @Email String email,
        @NotBlank String password) {}
```

The two fields needed to log in locally.

### `dto/AuthResponse.java`

```java
public record AuthResponse(
        String token,        // the JWT
        String tokenType,    // "Bearer"
        long expiresInMs,    // how long the token is valid
        String email,
        String fullName,
        String authProvider, // LOCAL / GOOGLE / MICROSOFT
        Set<String> roles) {}
```

This is what the REST API returns after a successful login/registration, and it's
also used internally to build the JWT cookie. `java.util.Set` holds the role names.

## 4.8 Exceptions

### `exception/AuthException.java`

```java
public class AuthException extends RuntimeException {
    public AuthException(String message) { super(message); }
}
```

A simple custom exception thrown for business errors: duplicate email, wrong
password, blocked account, etc. Being a `RuntimeException` means we don't have to
declare it everywhere.

### `exception/ApiExceptionHandler.java`

Imports:

| Import | What it does |
|--------|--------------|
| `org.springframework.http.HttpStatus` / `ResponseEntity` | Build an HTTP response with a status code + body. |
| `org.springframework.web.bind.MethodArgumentNotValidException` | The exception Spring throws when `@Valid` fails. |
| `org.springframework.web.bind.annotation.ExceptionHandler` | Marks a method as handling a given exception type. |
| `org.springframework.web.bind.annotation.RestControllerAdvice` | Applies these handlers across all controllers, returning JSON. |
| `java.util.HashMap` / `Map` | Build the JSON error body. |

```java
@RestControllerAdvice(basePackages = "com.ecommerce.controller")
public class ApiExceptionHandler {

    @ExceptionHandler(AuthException.class)
    ... returns 400 { "error": "<message>" }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    ... returns 400 { "error": "Validation failed", "fields": { ... } }
}
```

So instead of an ugly stack trace, API callers get a tidy JSON error. (The HTML
form flow catches `AuthException` itself and re‑renders the page with a message —
see file 7.)
